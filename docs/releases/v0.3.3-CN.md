# WANIPv4-Watcher v0.3.3 中文发布说明

## 本版重点

在 WebUI「程序更新」栏目增加可配置的直连、HTTP 和 SOCKS5 代理，解决路由器能访问 GitHub 源码/API、却无法顺利下载 Release 资产的问题。代理只用于程序更新，不改变 WAN IPv4 检测和邮件发送路径。

## 更新代理设置

- 新增直连、HTTP、SOCKS5 三种模式；服务器地址和端口使用独立输入框。
- 服务器地址支持 IPv4、IPv6 和 ASCII 域名；端口校验为 1–65535。
- HTTP 与 SOCKS5 均支持可选用户名/密码认证；SOCKS5 使用 RFC 1928 / RFC 1929 标准握手。
- SOCKS5 将目标域名发送给代理解析，避免为 GitHub 目的域名先进行本地 DNS 查询。
- 可以单独保存代理设置；切换到直连会清除代理地址与认证信息。支持显式清除已保存的代理认证。
- 配置仍保存在原有 JSON 配置文件中；梅林 JFFS 配置继续使用 600 权限。旧配置没有 `update_proxy` 时自动采用直连，不影响原 SMTP、检测时间、WAN 接口和设备 TAG。
- Web API 可读取代理模式、地址、端口和是否已配置认证，但不会回传代理用户名或密码；输入框留空保持旧凭证。

## 代理测试与更新链路

- 增加「测试代理」按钮，先访问 GitHub 最新 Release API，再通过 Release 资产的真实下载地址获取 `checksums.txt`，验证 API 与 Release/CDN 两段网络路径均可用。
- 最新版本查询、当前架构二进制下载、SHA-256 清单下载共用同一代理客户端。
- 直连模式明确不读取 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量；选择 HTTP 或 SOCKS5 时只使用配置的代理。
- 代理失败时显示对应错误，不静默回退直连，也不在错误信息中打印代理密码。
- WAN IPv4 四个国内检测源仍按原来的直连方式运行；QQ SMTP 邮件不使用更新代理，不会因 GitHub 代理切换而改变出口。

## 实现与验证

- SOCKS5 客户端由 Go 标准库实现，不增加第三方模块；保持 `CGO_ENABLED=0` 和 ARM64、ARMv7、AMD64、MIPS 大小端/浮点 ABI、RISC-V64 的既有构建目标。
- 增加代理参数校验、HTTP 代理认证、SOCKS5 用户名/密码认证与远端 DNS、直连环境隔离、代理设置持久化和 API 凭证脱敏测试。
- GitHub Actions 执行 `go test ./...`、`go vet ./...`、Shell 语法检查和全部 8 个 Linux 架构构建。
- CI 成功不替代 RT-AC86U 386.9_0 KoolShare 设备上的实际代理测试与升级验收；首次测试建议先保存代理，再点击 WebUI 的「测试代理」。

## Merlin / KoolShare 安装器补充兼容

- 安装下载器增加对 BusyBox Wget applet 和 Merlin/KoolShare 常见可执行文件目录的搜索，避免只检查交互 Shell 的 PATH。
- 增加受控预下载模式：当交互 Shell 的 wget 是别名/函数、无法被安装器内部 `sh` 调用时，可预先下载 ARM64 二进制、checksums.txt 和 bootstrap-merlin.sh 到指定的 /tmp 文件名，再设置 `WANIPv4_WATCHER_PRELOADED=1` 运行安装器。
- 预下载模式不会绕过 SHA-256 或 Shell 语法校验；安装器仍须确认 Release 校验文件含对应 ARM64 资产，二进制校验成功后才替换 JFFS 文件。
