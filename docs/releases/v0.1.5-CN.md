# WANIPv4-Watcher v0.1.5 中文发布说明

## 版本重点

本版的主要目标是把 Padavan 启动脚本变短、降低手工维护成本：路由器只需保留邮件配置与一个 GitHub 启动器调用，下载程序、校验、赋予执行权限和进程管理由仓库托管的 scripts/bootstrap.sh 完成。

## 具体变化

### Padavan 页面只需配置三项邮件信息

首页快速部署代码只需要填写：

- WANIPV4_SMTP_USER：用于发送告警的 QQ 邮箱地址。
- WANIPV4_SMTP_AUTH_CODE：QQ 邮箱 SMTP 授权码，不是 QQ 登录密码。
- WANIPV4_SMTP_TO：告警接收地址。

启动区块应追加到 Padavan 的“参数设置 → 脚本 → 在路由器启动后执行”，不要覆盖既有的 TCP、drop_caches、udpxy 等其他启动命令。路由器不需要手动下载或复制 Go 二进制。

### GitHub 启动器集中处理安装流程

- 启动器根据三项环境变量在 /tmp 中生成运行配置，文件权限设置为 600；启动 Go 进程前清除导出的凭证变量。
- 从 GitHub 最新 Release 下载 MIPSLE soft-float 二进制与 SHA-256 清单，校验通过后才赋予执行权限并替换运行程序。
- 缺少 sha256sum 和 openssl 时拒绝运行未经校验的文件；下载失败、缺少校验条目或校验不一致都会报错退出。
- 集中提供 start、stop、status 操作，并检查 PID 对应进程确实是本工具，避免只根据一个旧 PID 文件就误杀其他进程。
- 运行配置、程序、PID 和日志位于 /tmp，重启后由 Padavan 启动入口重新生成/下载，减少对闪存的写入。
- 兼容旧的 SSH 安装方式：如果没有新的临时配置且 /etc/storage/wanipv4-watcher.json 存在，可继续读取旧配置。

### 文档与自动化检查

- 将短启动入口、三项参数含义和“追加而不是覆盖”的提醒放到仓库首页，降低首次部署出错概率。
- 保留旧版 SSH 安装/卸载脚本供维护使用。
- CI 增加 bootstrap、安装器和卸载器的 Shell 语法检查，并继续进行 Go 测试、静态检查和两个目标平台的构建。

## 升级方式

如果已使用 v0.1.4 或更早版本，可以采用仓库首页的推荐网页启动方式，先备份现有 Padavan 启动脚本，再按文档追加新区块并填写三项邮件信息。旧版 SSH 安装入口仍保留，现有 /etc/storage 配置也提供兼容回退；不要在没有检查的情况下覆盖已有自定义启动内容。

## 测试与交付

本版通过 Go 单元测试、go vet、Shell 语法检查、Linux MIPSLE soft-float 路由器目标和 Linux AMD64 诊断目标的构建发布流程。Release 附带二进制、源码归档、SHA-256 校验清单和中文构建报告。

## 已知限制

- GitHub 下载和校验成功不代表设备实际能访问每个检测源，也不能证明 QQ 邮件一定送达。
- 仍需在真实 K2P Padavan 设备上确认系统时钟、WAN 接口识别、可用哈希工具及 SMTP 投递。
- QQ 授权码会存在 Padavan 持久化启动脚本的配置文本中，请只在自己的路由器设置中填写，不要公开发布或提交到 GitHub。
