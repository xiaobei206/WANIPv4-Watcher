# WANIPv4-Watcher v0.3.2 中文发布说明

## 本版重点

为多路由器部署增加设备身份 TAG，把邮件从“状态变化通知”调整为“每轮检测结果通知”，将应用运行日志改为纯 RAM 缓冲，并修复 ASUSWRT-Merlin / KoolShare 本地命令布局兼容性。

## 设备昵称与备注

- WebUI 增加设备昵称 / 邮件 TAG 和设备备注。
- 每台路由器可配置唯一昵称，例如“苏州主路由”“书房备用路由”；备注可描述宽带、机柜位置或用途。
- 邮件主题以 TAG 开头，固定产品标识放在末尾：
  - `[TAG正常] WAN 与公网出口 IPv4 一致 [WANIPv4-Watcher]`
  - `[TAG告警] WAN 口检测到非公网 IPv4 [WANIPv4-Watcher]`
  - `[TAG测试] 邮件发送测试 [WANIPv4-Watcher]`
- 备注、主机名、版本等身份信息写入邮件正文。
- 配置读取接口只返回是否已设置，不返回实际昵称、备注、WAN 配置或 SMTP 凭证；留空字段保持原值，保存后继续清空输入框并折叠显示“已保存”。
- 长中文主题使用 RFC 2047 编码分段折行，避免长 TAG 导致单个编码词过长。

## 每轮检测发送邮件

- 每次计划检测都会发送一封结果邮件，不再只在状态切换时通知。
- `healthy` 发送普通优先级正常邮件。
- `private_wan`、`mismatch` 发送高优先级告警邮件。
- `unknown` 同样发送高优先级告警邮件，明确提示本轮无法形成可靠结论，而不是静默。
- 告警/未知邮件增加 `X-Priority: 1 (Highest)`、`Importance: High`、`X-MSMail-Priority: High`；正常和测试邮件不添加优先级头。
- 默认 07:00、19:00 检查，即每台路由器正常情况下每天发送两封检测结果邮件。SMTP 失败时每轮最多重试 3 次、间隔 10 秒；重试不重复执行检测。
- WebUI“检测测试（不告警）”保持只展示检测结果，不发送邮件；正式立即检测和 CLI `-once` 发送本轮结果邮件。

## 纯 RAM 运行日志

- 删除基于文件的 512 KiB + .1 滚动日志写入器。
- 新增进程内存日志缓冲，默认最大 128 KiB、最长保留 7 天；任一上限达到时淘汰最旧条目。
- WebUI 读取内存缓冲最近日志；程序或路由器重启后日志清空，不写 JFFS、不产生持续文件写入。
- 旧配置字段 `log_file` 保留用于兼容，但不再使用；梅林启动诊断单独放在 RAM 文件 `/tmp/wanipv4-watcher-bootstrap.log`，每次启动前截断。

## Merlin / KoolShare 兼容性

根据 RT-AC86U、ASUSWRT-Merlin 386.9_0 KoolShare 实机控制台输出，修复：

- root 判断不再强制依赖 `id` 命令，优先读取 `/proc/self/status` 的 UID。
- NVRAM 命令先查 PATH，找不到时回退 `/bin/nvram`。
- SHA-256 校验先查 `sha256sum`，再搜索 PATH 和多个常见绝对路径中的 OpenSSL，包括 `/usr/sbin/openssl`。
- curl 下载失败后清理不完整文件并回退 GNU Wget；不在仓库写入任何特定代理地址，也不降低 SHA-256 校验要求。
- 临时导出的 HTTP(S)_PROXY 可供当前下载/更新命令使用；管理脚本启动常驻监控进程前会清除代理环境变量，防止下载代理改变日常检测流量路径。
- 安装器与管理脚本不再静默隐藏下载失败：分别输出 curl 错误、Wget HTTP/连接信息和退出状态，便于区分源码站点与 Release/CDN 域名可达性；代理值不会输出到日志。
- 安装器和卸载器继续只管理 WANIPv4-Watcher 自己的 JFFS 配置、服务启动标记区块和 watchdog 任务；不覆盖用户其他启动脚本。

## 配置兼容与验证

- v0.3.1 已保存的 SMTP 主机、授权码、发件人、收件人、检测时间和 WAN 接口升级保留；新增设备字段缺失时默认为空。
- Shell 安装仍不询问业务配置，全部通过 WebUI 设置。
- 新增设备身份脱敏、邮件优先级、长主题折行、RAM 日志保留/容量和配置保存测试。
- 构建结果和 RT-AC86U 实机升级/邮件投递验收情况以本次 GitHub Actions 与用户设备结果为准；CI 通过不替代真实邮件客户端显示验证。
