# WANIPv4-Watcher v0.1.3 中文发布说明

## 版本重点

本版将原来的高频轮询改成按路由器本地时间每天两个固定时刻检查，并补齐 Padavan 网页“在路由器启动后执行”入口的部署文档和启动重试行为。升级后，旧配置缺少新字段时会回退到默认时刻。

## 具体变化

### 每天 07:00、19:00 检测

- 默认使用路由器系统本地时区，每天上午 07:00 和晚上 19:00 各检查一次。
- 不再每 30 秒反复查询，也不会在程序刚启动时额外立即执行一次检查；例如 08:00 启动后，会等待当天 19:00 的下一次计划任务。
- 新增 check_times 配置并验证 HH:MM 格式、重复时刻和数量上限。旧配置没有 check_times 时自动补为 07:00、19:00；interval_seconds 字段为兼容旧 JSON 保留，但不再决定默认调度。
- 增加下一次计划检测时间的计算和相关测试。

### 邮件失败重试不重复检测

- 每轮检测完成后，若发送告警邮件失败，最多重试 3 次，每次等待 10 秒。
- 重试只针对同一条邮件通知，不会因为 SMTP 失败而再次请求外部 IP 服务或重复计算 WAN 状态。

### Padavan 网页启动入口

- 提供独立的中文说明，指导将启动区块追加到“参数设置 → 脚本 → 在路由器启动后执行”，保留用户已有的 TCP、drop_caches、udpxy 等其他命令。
- 每次开机在 /tmp 重建运行配置，等待网络稍微稳定后下载 GitHub 上的启动器，并在启动失败时最多重试 12 次、每次等待 10 秒。
- 程序、PID、日志和运行配置尽量放在 /tmp，减少反复写闪存；旧式 SSH 安装器存放在 /etc/storage 的配置仍可通过启动器回退读取。
- 启动器会在下载二进制后校验 SHA-256；没有可用的 SHA-256 校验工具时拒绝运行未经校验的文件。

## 升级注意事项

- 如果是由旧版配置升级，check_times 缺失时会采用默认时刻，不需要为了这个字段手工重写整个 JSON。
- 请确认 Padavan 路由器的系统时间、时区设置正确，否则 07:00 和 19:00 会按错误的本地时钟执行。
- 该版本仍使用上一版的海外外部检测源；v0.1.4 才替换为 IPIP、3322、CIP.cc 和 IP9。

## 测试与交付

新增计划时刻验证、重复/非法时间测试，以及邮件重试相关路径检查。本版通过 Go 测试、go vet、Shell 脚本语法检查和 Linux MIPSLE soft-float / AMD64 构建流程。自动化构建未覆盖每一款 Padavan 固件的真实启动行为。

## 已知限制

- 时区依赖路由器系统本地时间。
- 国内网络对旧版海外检测源的可达性仍可能不稳定。
- 实际 WAN 接口、QQ SMTP 授权码和邮件到达情况仍需用户设备验证。

### 型号与 ABI 注意事项

- 表中型号用于快速定位芯片平台，**不表示该型号所有硬件版本、所有地区版或原厂固件都经过 WANIPv4-Watcher 实机验证**。同一商品名可能跨硬件版本更换 SoC，必须核对设备标签、硬件版本及系统信息。
- 特别注意：小米 AX3000T 的 RD03 / RD23 是 MediaTek MT7981B；新款 RD03v2 使用不同的 Qualcomm 硬件，不能直接套用 MT7981B 这一行。
- **MIPS 的大小端与浮点 ABI 是两个独立条件**：`mipsle` 与 `mips` 不能互换；`softfloat` 与 `hardfloat` 也不能互换。请以路由器当前 Linux 固件的实际 ELF / 软件包架构为准，不要只按品牌、商品名或 CPU 系列选择。
- 默认原厂固件若不是 Linux（例如专有 RouterOS），即使 CPU 芯片相同，也不能直接运行本项目的 Linux 二进制；需要设备运行兼容的 Linux 固件/环境。
- 早期 Release 的资产集和命名曾随项目演进而变化；本表统一说明当前稳定资产名。**新安装请从最新 Release 下载**，不要假设早期历史 Release 一定包含表内全部文件。
- 项目不编译 ARMv5、ARMv6 或 32 位 x86（386）。所有构建使用 `CGO_ENABLED=0`；CI 交叉编译通过不等于每个列举型号均已实机验证。
