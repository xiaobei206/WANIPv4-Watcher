# WANIPv4-Watcher v0.2.0 中文发布说明

## 版本重点

v0.2.0 将项目从重点面向 K2P/Padavan 扩展为支持多种 Linux 路由器与软路由架构，并新增 ASUSWRT-Merlin 的安装、开机启动、更新、诊断和卸载流程。本版仍保留 K2P 的 MIPSLE soft-float 产物及原有 Padavan 部署入口。

## 一、多架构 Release 产物

GitHub Actions 新增并统一构建以下 Linux 目标，全部使用 CGO_ENABLED=0：

| Release 资产名 | 目标架构 | 选择注意事项 |
| --- | --- | --- |
| wanipv4-watcher-linux-arm64 | ARM64 / AArch64 | ASUS RT-AC86U（梅林）等 ARM64 设备 |
| wanipv4-watcher-linux-armv7 | 32 位 ARMv7 | 必须匹配固件使用的 ABI |
| wanipv4-watcher-linux-amd64 | x86-64 | x86-64 OpenWrt/iStoreOS 软路由和迷你主机 |
| wanipv4-watcher-linux-mipsle-softfloat | 小端 MIPS soft-float | K2P / Padavan 的现有目标 |
| wanipv4-watcher-linux-mipsle-hardfloat | 小端 MIPS hard-float | 仅用于对应硬浮点 ABI 的固件 |
| wanipv4-watcher-linux-mips-softfloat | 大端 MIPS soft-float | 使用前需核对大小端和浮点 ABI |
| wanipv4-watcher-linux-mips-hardfloat | 大端 MIPS hard-float | 使用前需核对大小端和浮点 ABI |
| wanipv4-watcher-linux-riscv64 | 64 位 RISC-V | 主要面向 Linux 设备/开发板，实机覆盖有限 |

本版不构建 ARMv6、ARMv5 或 32 位 x86（386）。架构相同也不代表固件 ABI 一定兼容；特别是 MIPS，必须同时确认大小端及 soft-float/hard-float。

## 二、新增 ASUSWRT-Merlin 安装器

- 新增 install-merlin.sh、bootstrap-merlin.sh 和 uninstall-merlin.sh，并提供中文指南 MERLIN-INSTALL-CN.md。
- 安装器检查当前用户权限、uname -m 是否为 aarch64/arm64、/jffs 是否可写、nvram 命令以及梅林的 JFFS 自定义脚本开关；不满足条件会明确停止。
- 首次安装时根据默认路由给出 WAN 接口建议，并交互询问发送邮箱、QQ 邮箱 SMTP 授权码和收件地址。交互读取授权码时尽量关闭终端回显。
- 配置写入 /jffs/configs/wanipv4-watcher.json，权限设为 600；已有配置会保留。
- 管理器安装在 /jffs/scripts/wanipv4-watcher，只管理 services-start 中带有本工具标记的区块，保留用户其他启动内容。
- 运行时从最新 Release 下载 ARM64 二进制，校验 SHA-256 后才运行。程序、PID 和日志位于 /tmp；管理器支持 start、stop、restart、update、status、check-config、once、test-email、logs。
- 卸载器只删除本工具的启动区块与临时运行文件，默认保留永久配置和邮件凭证。

## 三、统一的发布交付与说明

- README 首页新增通用 Linux 手动部署和架构选择表，再分别链接 Padavan、Merlin 等系统专用指南。
- Release 为资产增加用途标签，并附带源码归档、中文构建报告和 SHA-256 校验清单。
- 构建报告描述自动化构建范围，并明确声明 CI 成功不等于所有型号均已完成实机验收。

## 安装与升级

- ASUSWRT-Merlin 用户请先启用 Administration → System 中的 Enable JFFS custom scripts and configs，再按 [梅林中文安装指南](https://github.com/xiaobei206/WANIPv4-Watcher/blob/main/docs/MERLIN-INSTALL-CN.md) 执行安装命令。
- Padavan 用户继续使用 README 和 Padavan 文档中的既有入口，无需改用 ARM64 文件。
- 通用 Linux 用户请按架构表选取匹配文件，并在执行前根据 SHA-256 清单校验；不要仅凭设备品牌或 CPU 名称猜测 ABI。

## 自动化验证与实机边界

GitHub Actions 对单元测试、go vet、scripts 目录下的 Shell 语法以及列出的架构进行构建。此验证仅说明自动化流程通过，不代表已经在所有路由器型号上实际运行。ASUS RT-AC86U 的当前环境已观察到 uname -m 返回 aarch64，默认路由优先接口为 ppp0；安装后仍应验证程序启动、检测源可达性和 QQ SMTP 送达。

### 型号与 ABI 注意事项

- 表中型号用于快速定位芯片平台，**不表示该型号所有硬件版本、所有地区版或原厂固件都经过 WANIPv4-Watcher 实机验证**。同一商品名可能跨硬件版本更换 SoC，必须核对设备标签、硬件版本及系统信息。
- 特别注意：小米 AX3000T 的 RD03 / RD23 是 MediaTek MT7981B；新款 RD03v2 使用不同的 Qualcomm 硬件，不能直接套用 MT7981B 这一行。
- **MIPS 的大小端与浮点 ABI 是两个独立条件**：`mipsle` 与 `mips` 不能互换；`softfloat` 与 `hardfloat` 也不能互换。请以路由器当前 Linux 固件的实际 ELF / 软件包架构为准，不要只按品牌、商品名或 CPU 系列选择。
- 默认原厂固件若不是 Linux（例如专有 RouterOS），即使 CPU 芯片相同，也不能直接运行本项目的 Linux 二进制；需要设备运行兼容的 Linux 固件/环境。
- 早期 Release 的资产集和命名曾随项目演进而变化；本表统一说明当前稳定资产名。**新安装请从最新 Release 下载**，不要假设早期历史 Release 一定包含表内全部文件。
- 项目不编译 ARMv5、ARMv6 或 32 位 x86（386）。所有构建使用 `CGO_ENABLED=0`；CI 交叉编译通过不等于每个列举型号均已实机验证。
